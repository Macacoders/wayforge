# AI Change Log: 2026-11

## 2026-11-03

- **PR #274 review follow-up (Issue #239):** hardened the update notifier per maintainer review. The gate is now the affirmative `WAYFORGE_UPDATE_CHECK`: only `1` or `true` (trimmed, case-insensitive) enables the check; unset/empty/`0`/`false`/other disables it, and `WAYFORGE_NO_UPDATE_CHECK` is fully removed. `WAYFORGE_RELEASE_ROOT`, `WAYFORGE_NOTIFIER_CACHE`, and `WAYFORGE_VERSION` are test-only seams honored only when `WAYFORGE_NOTIFIER_TEST=1` (in production they are ignored; `WAYFORGE_VERSION` must also parse as semver). Egress is constrained: the production release root is the constant `https://github.com/Macacoders/wayforge/releases`, the redirect `Location` must be HTTPS on `github.com` under `/Macacoders/wayforge/releases/tag/` (everything else is a silent no-op), the response body is cancelled before returning/throwing, and the `User-Agent` is the constant `wayforge-update-notifier` (the installed version is never sent). The `session.created` hook is fire-and-forget — it triggers `checkAndNotify()` and returns immediately, never awaiting the network. Cache writes are atomic (same-directory temp file + rename, temp cleanup on failure, symlink-safe final path). The ADR was renumbered to [ADR-0049](../decisions/ADR-0049-runtime-update-notifier.md) (git mv; #272 owns ADR-0048 for cosign) and README/architecture/RELEASE/log/plan references updated. `make check` now runs `node --check` on the three plugin `.js` files. Validation (agent): `npx vitest run cli/tests/unit/wayforge-update-plugin.test.ts` green (64/64, including redirect rejection, ignored production seams, UA privacy, body cancellation, atomic-write cleanup, and the non-blocking hook). Manual runtime validation — OpenCode, Kilo CLI, Kilo VS Code, including the installed-but-unregistered check (no cache file, no network request, no toast) — remains **outstanding and human-owned**.

## 2026-11-02

- Completed plan `docs/ai/plans/2026-11-02_103741-issue-239-runtime-update-notifier-opt-in.md` (2/2 tasks, Issue #239, parent #48): opt-in update notifier plugin for OpenCode and Kilo Code. **Task 1** (`e66bd10`) added `base/plugins/wayforge-update/{core,index,kilo}.js` + `package.json` (dependency-free: Node built-ins + global `fetch`) and `cli/tests/unit/wayforge-update-plugin.test.ts`. The check is disabled by default: only `WAYFORGE_UPDATE_CHECK=1` or `true` (trimmed, case-insensitive) enables it; unset/empty/`0`/`false`/other keeps it disabled with no cache read, no fetch, and no toast. When enabled it reads the installed version (`WAYFORGE_VERSION` test-only seam, else `<prefix>/share/wayforge/VERSION`), checks the release root at most once per 24 hours (manual redirect, 5s timeout), and shows a one-time `client.tui.showToast` per newer version: `wayforge v<latest> is available (installed v<current>). Run \`wfg upgrade\` to update.` The plugin owns `<user cache>/wayforge/update-notifier.json` (`WAYFORGE_NOTIFIER_CACHE` is a test-only seam) and never touches CLI state; all network/cache/toast failures are silent no-ops and never block the session. **Task 2** (this commit) documented the notifier: README "Optional: update notifier" subsection (manual registration, gate values, toast, cache, `--force` re-apply caveat), `docs/ai/architecture.md` (entrypoints, plugin-owned cache boundary, interim manual registration; CLI commands still never check for releases), `RELEASE.md` (optional plugin, default installs unchanged), and [ADR-0049](../decisions/ADR-0049-runtime-update-notifier.md).
