# AI Change Log: 2026-11

## 2026-11-03

- SignPath Foundation denied the project's free OSS code-signing application on 2026-11-03 (submitted 2026-11-02) because the project did not yet show sufficient public visibility/reputation. Decision: remove the SignPath application artifacts (`CODE_SIGNING_POLICY.md`, `.signpath/artifact-configuration.xml`) and the README claim that Windows artifacts are Authenticode-signed; the project ships unsigned Windows artifacts with `wayforge-checksums.txt` (SHA-256) integrity verification. New status page `docs/security/windows-code-signing.md` records the denial, the alternatives evaluated (Microsoft Store MSIX free but Store-only and not a drop-in for `install.ps1`/`wfg.exe`, evaluated and rejected; OSSign/Necessary Code Signing require an established user base; self-signed is not public trust; Certum Open Source and Azure Artifact Signing are paid and not adopted), SmartScreen guidance, and the revisit trigger. Plan: `docs/ai/plans/2026-11-03_100026-issue-240-remove-signpath-artifacts.md`; the old signing plan `docs/ai/plans/2026-10-28_113250-issue-240-installer-signing-edr-hardening.md` is marked `status: superseded` with its body preserved as a historical record.
