- Completed plan `docs/ai/plans/2026-11-02_103741-issue-239-runtime-update-notifier-opt-in.md` (2/2 tasks, Issue #239, parent #48): opt-in update notifier plugin for OpenCode and Kilo Code. **Task 1** (`e66bd10`) added `base/plugins/wayforge-update/{core,index,kilo}.js` + `package.json` (dependency-free: Node built-ins + global `fetch`) and `cli/tests/unit/wayforge-update-plugin.test.ts`. The check is disabled by default: only `WAYFORGE_NO_UPDATE_CHECK=0` or `false` (case-insensitive) enables it; unset/empty/`1`/`true`/other keeps it disabled with no cache read, no fetch, and no toast. When enabled it reads the installed version (`WAYFORGE_VERSION` seam, else `<prefix>/share/wayforge/VERSION`), checks `${WAYFORGE_RELEASE_ROOT || default}/latest` at most once per 24 hours (manual redirect, 5s timeout), and shows a one-time `client.tui.showToast` per newer version: `wayforge v<latest> is available (installed v<current>). Run \`wfg upgrade\` to update.` The plugin owns `<user cache>/wayforge/update-notifier.json` (`WAYFORGE_NOTIFIER_CACHE` is a test/manual seam) and never touches CLI state; all network/cache/toast failures are silent no-ops and never block the session. **Task 2** (this commit) documented the notifier: README "Optional: update notifier" subsection (manual registration, gate values, toast, cache, `--force` re-apply caveat), `docs/ai/architecture.md` (entrypoints, plugin-owned cache boundary, interim manual registration; CLI commands still never check for releases), `RELEASE.md` (optional plugin, default installs unchanged), and [ADR-0048](../decisions/ADR-0048-runtime-update-notifier.md).
