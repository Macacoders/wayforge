## Evidence contract

| Measure | Required independent evidence | What it cannot establish |
| --- | --- | --- |
| Verified resolution | Upstream verifier output and task/result identity | Role separation or skill use |
| `delivery → code → reviewer` | Runtime events or session records with agent identities, parent/child linkage, and source revision | Quality of the review from agent prose alone |
| Skill load | Actual `skill(name)` tool invocation or equivalent runtime event | Skill applicability or correct application |
| Stop/revision compliance | Dispatch, verdict, and revision events with ordering | An unobserved decision or inferred approval |
| Tokens/cost/latency | Provider or runtime usage records covering every child agent and failure | A hard in-flight spend cap unless the provider or proxy enforces one |

Missing events are `unverifiable`. A successful verifier with no observable `delivery`, `code`, and `reviewer` chain does **not** measure the whole Wayforge harness. Neither task is currently pre-labelled for relevant-skill recall. A one-task subset is exploratory and is not an official leaderboard score.

## Isolation preflight: fail closed

BenchFlow installs and launches OpenCode **inside the task sandbox**. The task package supplies an environment image, source files, and commands the agent may run. Its verifier runs after the agent. [The upstream registry](https://github.com/benchflow-ai/benchflow/blob/v0.6.3/src/benchflow/agents/registry.py) describes provider environment propagation into the sandbox; the public [BenchFlow CLI reference](https://www.benchflow.ai/docs/benchflow/reference/cli) exposes `--agent-env`. Task-controlled shell processes can read or use an agent credential in this container. BenchFlow's [verifier hardening](https://github.com/benchflow-ai/benchflow/blob/main/docs/sandbox-hardening.md) protects the verifier after agent execution; it is not credential isolation during the task.

On 2026-10-31 the maintainer explicitly authorized one exception: a newly created, dedicated Zen key for free models with zero paid use, after checking the Docker mounts. The key may be readable by task commands. This approval does not cover a personal key, OpenCode Go, paid attempts, or host credentials. A $0 all-spend service-account budget and disabled auto-reload are the available provider controls to inspect; they are **not** a model-specific key restriction or an in-flight hard cap. Confirm the exact key permissions, budget, model list, and current price before the pilot. [OpenCode Console API keys](https://dev.opencode.ai/v2/docs/console/api), [budgets](https://dev.opencode.ai/v2/docs/console/budgets), and [model prices](https://opencode.ai/v2/docs/console/models/) are dynamic provider documentation.

The maintainer's checkout is on a normal workstation. The plan does not require a disposable VM; this alone is not a no-go. The selected task has no declared Compose services or socket mount, but BenchFlow's dynamic Docker mounts and the host's secret/config exposure still require inspection. A VM could limit host exposure but would not separate a provider key from task subprocesses inside the same agent sandbox.

For the authorized free-model attempt, a maintainer must record and inspect all of the following for the **exact pinned runtime**:

1. External SkillsBench checkout path, BenchFlow checkout or installed package location, disposable workspace path, jobs/output path, and each realpath and full Git SHA. The current repository boundary does not authorize accessing those paths.
2. Task image, Docker Compose services, mounts and their read/write modes, sandbox user, capabilities, privileged flag, Docker socket and host secret/config directory exposure. Reject privileged containers, socket mounts, broad writable host mounts, or host secret/config mounts.
3. Every task-controlled process and its environment, process namespace, filesystem, network route, and access to agent/proxy credentials. For this exception, explicitly record that task processes can obtain the dedicated key; confirm they cannot obtain unrelated host auth state. Do not print credential values in the evidence.
4. Exact recipient of the dedicated key, its service-account permissions and $0 all-spend ceiling. Check logs, trajectories, and exported sessions for accidental raw-key persistence. Never pass the key on a command line.
5. A fixed model and OpenCode package version in the sandbox, plus evidence that installed Wayforge config is loaded and `/deliver` invokes `delivery`, `code`, and `reviewer` with inspectable events. If ACP cannot expose those events, test a supported session export in the same isolated environment before claiming observability.
6. A finite budget declaration: model price source/date, maximum input and output tokens per attempt, maximum attempt wall time, maximum attempts per variant, maximum variants, total run ceiling, and the provider account/project spending ceiling. Record whether each is enforced by provider/proxy/runtime or only checked between attempts. No missing usage, automatic retries, or silent continuation.
