# Issue #243 / PR #256 review fixes Implementation plan

**Goal:** Close the four review findings on PR #256 by making both installers fall back to an unverified install **only** when `wayforge-checksums.txt` is confirmed absent (HTTP 404), aborting before any prefix change on every other checksum-download failure, making the Pester suite portable to Linux `pwsh`, making the Bats suite runnable on the project's Bats 1.2.1, and merging `develop` so the PR is conflict-free and the gates are green.

**Architecture:** Keep the existing installer structure (single-file POSIX sh / PowerShell with no shared library). Add a tri-state checksum fetch to each installer: `0 = downloaded`, `1 = asset absent (404)`, `2 = download failure`, then branch to verify / warn-and-continue / abort. Tests drive the tri-state through the existing stubbed HTTP layer (`curl`/`wget` for bats, `Invoke-WebRequest` for Pester) and add one non-404 failure case per installer. Resolve the single merge conflict in `docs/ai/logs/2026-10.md`, rerun every gate, and report agent-completed checks separately from the human-only installs.

**Tech Stack:** POSIX `sh` (`install/install.sh`), PowerShell 5.1/7 (`install/install.ps1`), Bats (`tests/bash/install_sh.bats`), Pester 5/6 (`tests/powershell/install.Tests.ps1`), `curl`/`wget` status capture, `Invoke-WebRequest` exception status inspection, Git merge.

**Scope classification:** `multi-task`

**Plan rationale:** Four independently reviewable slices: the develop merge (foundational, must land before validation), the POSIX slice, the PowerShell slice, and the cross-cutting validation/report slice. More than three tasks is justified because the merge is a distinct commit type (merge commit) and the follow-up report must quote results from both installer tasks. ### Task 2: POSIX installer checksum-fetch triage + Bats 1.2.1 compatibility

**Objective:** `install/install.sh` warns and installs unverified only on HTTP 404 for `wayforge-checksums.txt`, aborts before any prefix mutation on every other checksum-download failure, and the Bats suite runs on the project's Bats 1.2.1.

**Files:**
- Modify: `install/install.sh` (checksum fetch helper, `run_install` ordering/branching)
- Modify: `tests/bash/install_sh.bats` (stub, helper, new cases, remove 1.5-only APIs)
- Validate: `tests/bash/install_sh.bats`

**Step 1: Establish expected behaviour**

- Add a tri-state fetch specifically for the checksum asset: return `0` = downloaded, `1` = confirmed absent (HTTP 404), `2` = any other failure.
- `curl`: do **not** use `-f` for this request. Request with `-sS -L -o <dest> -w '%{http_code}'`, capture the status, and classify: `200` → 0, `404` → 1, every other status → 2. A non-zero curl exit (DNS, TLS, timeout, connection reset) → 2.
- `wget`: capture `--server-response` headers (to a temp file or stderr), run with `-O <dest>`; classify the last `HTTP/... <code>` as 200/404/other. `wget` exit codes 4/5/8 without a 404 header → 2.
- `run_install` branch:
  - `0` → existing `verify_asset` calls for the binary and share.
  - `1` → remove the empty temp file, print the existing warning `warning: wayforge-checksums.txt is unavailable for ${TAG}; skipping checksum verification` to stderr, continue unverified.
  - `2` → print `error: failed to download wayforge-checksums.txt for ${TAG} (HTTP <code>); aborting without changes` (omit the HTTP parenthetical for transport failures) to stderr and `exit 1` **before** `ensure_node`, `mkdir`, `chmod`, `mv`, `tar`, or PATH edits.
- The binary and share downloads keep using `download()` (`curl -fsSL` / `wget -q`); a failure there still aborts before mutation via `set -e`.
- Bats compatibility: remove `bats_require_minimum_version`; remove `run --separate-stderr`; no other 1.5-only options. Use plain `run` and redirect the install command's stderr to `$TEST_TMPDIR/stderr.log`, then read that file in assertions. This works on 1.2.1 and current Bats.
