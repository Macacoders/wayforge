# ai-config → wayforge rename (command `wfg`) Implementation plan

**Goal:** Rename the project from `ai-config` to `wayforge`, rename the invoked CLI command to `wfg`, and repoint the GitHub location to `Macacoders/wayforge` across all *living* source — a clean break with no migration shims, ahead of the v1.0.0 release.

**Architecture:** This is a cross-cutting identity rename, so tasks are split by file domain (CLI runtime, distribution/release, docs/templates) rather than by vertical slice — a horizontal split is required because a single identity token (the name) spans every layer. Derived identifiers use the full word `wayforge`; only the user-typed command is the short `wfg`. On-disk contracts (managed marker, prefix, env vars) change outright with no backward-compat readers.

**Tech Stack:** TypeScript (Commander CLI, vitest), POSIX shell + PowerShell installers, GitHub Actions (bun compile), Makefile, Markdown docs.

**Scope classification:** `multi-task` (3 tasks — within the 1–3 no-rationale budget)

## Canonical rename mapping

| Surface | Before | After |
|---|---|---|
| Project / brand | `ai-config` | `wayforge` |
| CLI command / `bin` | `ai-config` | `wfg` |
| GitHub repo | `Macacoders/ai-config` | `Macacoders/wayforge` |
| npm root package | `ai-config` | `wayforge` |
| npm CLI package | `ai-config-cli` | `wayforge-cli` |
| Install prefix | `~/.ai-config`, `%LOCALAPPDATA%\ai-config` | `~/.wayforge`, `%LOCALAPPDATA%\wayforge` |
| Env vars | `AI_CONFIG_HOME`, `AI_CONFIG_VERSION`, `AI_CONFIG_INSTALL_DIR`, `AI_CONFIG_NODE_BASE_URL` | `WAYFORGE_HOME`, `WAYFORGE_VERSION`, `WAYFORGE_INSTALL_DIR`, `WAYFORGE_NODE_BASE_URL` |
| Managed marker | `.ai-config-managed`, `.ai-config-managed.tmp`, `<file>.ai-config-managed` | `.wayforge-managed`, `.wayforge-managed.tmp`, `<file>.wayforge-managed` |
| Managed header / marker value | `// Generated by ai-config bootstrap`, `generated-by=ai-config-bootstrap` | `// Generated by wayforge bootstrap`, `generated-by=wayforge-bootstrap` |
| Log / banner prefix | `[ai-config]` | `[wayforge]` |
| Release artifacts | `ai-config-<os>-<arch>`, `ai-config-share-<v>.tar.gz/.zip` | `wayforge-<os>-<arch>`, `wayforge-share-<v>.tar.gz/.zip` |
| Share dir / installed binary | `share/ai-config`, `bin/ai-config[.exe]` | `share/wayforge`, `bin/wfg[.exe]` |
| PATH marker block | `# >>> ai-config >>>` | `# >>> wayforge >>>` |
| Temp dir prefix | `ai-config-<rand>` | `wayforge-<rand>` |
| Snippet helpers | `_ai_config_root`, `ai-setup-repo*`, `ai-uninstall-repo*` | `_wayforge_root`, `wayforge-setup-repo*`, `wayforge-uninstall-repo*` |

## Preserved (do NOT touch)

- `docs/ai/plans/**`, `docs/ai/decisions/**` (ADRs), `docs/ai/logs/**` — accurate history.
- `docs/ai/reports/**` — dated report (e.g. `toon-feasibility-2026-07-14.md`).
- `install/legacy/**` — deprecated installers; left unchanged (accepted: their baked-in repo/binary names become stale).
- Git history and the local working-directory name.

## Tasks

### Task 1: Rename CLI runtime identity and package metadata

**Objective:** The installed CLI reports itself as `wayforge`, is exposed as `wfg`, and reads `wayforge` env vars and on-disk markers.

**Files:**
- Modify: `cli/src/index.ts` (program name/`.name()`/descriptions, `AI_CONFIG_VERSION` → `WAYFORGE_VERSION`)
- Modify: `cli/src/lib/context.ts` (`[ai-config]` log prefix, `MANAGED_OPENCODE_HEADER`, `MANAGED_DIR_MARKER`)
- Modify: `cli/src/lib/manifest.ts` (all `.ai-config-managed*` paths, `generated-by=…` values, manifest header text)
- Modify: `cli/src/lib/source-dir.ts` (`AI_CONFIG_HOME` → `WAYFORGE_HOME`, `share/ai-config` → `share/wayforge`)
- Modify: `cli/src/lib/tracking.ts` (`LOCALAPPDATA/ai-config` and `~/.ai-config` → `wayforge`)
- Modify: `cli/src/lib/git.ts` (fallback repo URL, temp-dir prefix, comments)
- Modify: `cli/src/commands/install.ts` (`ai-config` strings, `AI_CONFIG_HOME` hint, `.ai-config-managed` guard, gh app comment)
- Modify: `cli/src/commands/uninstall.ts` (`.ai-config-managed` paths/messages)
- Modify: `package.json` (`name`, `description`), `cli/package.json` (`name`, `bin`, `description`)
- Modify: `package-lock.json`, `cli/package-lock.json` (workspace/package name fields)
- Modify: `cli/tests/unit/**/*.test.ts` (expectations: env var, marker, header, temp prefixes)
- Modify: `cli/tests/integration/run.sh` (marker paths — see Blocking decision 1)

**Step 1: Establish expected behaviour**

`wfg --version` prints `wayforge`'s version (from `WAYFORGE_VERSION`, default `0.1.0`); `wfg install --repo <r>` writes `.wayforge-managed`; `wfg uninstall --repo <r>` reads and removes `.wayforge-managed`; `resolveSourceDir()` honours `WAYFORGE_HOME` and the `share/wayforge` layout.

**Step 2: Add or update validation**

Unit tests already cover these paths; update their expected literals (env var names, `.wayforge-managed`, `# Generated by wayforge v…`, `// Generated by wayforge bootstrap`). No new tests needed — the rename is covered by existing assertions.

**Step 3: Write minimal implementation**

Apply the mapping table to every file listed above. Rename constants (`MANAGED_DIR_MARKER` value, `MANAGED_OPENCODE_HEADER` value) in one place (`context.ts`) and let `manifest.ts` consume them; replace the remaining hard-coded marker/path literals. Point the Commander program name/`.name()` at `wayforge` and keep the `bin` alias `wfg`. Update the `--define`/env read to `WAYFORGE_VERSION` only in `index.ts` (build wiring is Task 2).

**Step 4: Run test to verify pass**

Run:
- `npx vitest run cli/tests/unit`
- `cd cli && npx tsc --noEmit && npx eslint src/ && npx prettier --check src/`

Expected: all unit tests pass; typecheck/lint/format clean. *(Owner: agent)*

**Step 5: Commit**

`git add cli/src cli/tests cli/package.json cli/package-lock.json package.json package-lock.json`
`git commit -m "refactor: rename CLI runtime identity from ai-config to wayforge (wfg)"`

## Blocking decisions

1. **Stale integration test (pre-existing).** `cli/tests/integration/run.sh:85` invokes `install/bootstrap-legacy.sh`, which does not exist (actual path: `install/legacy/bootstrap-legacy.sh`). It also cross-compares the TS manifest against the legacy manifest at `.ai-config-managed`. With the clean break, TS emits `.wayforge-managed` while preserved legacy keeps `.ai-config-managed`, so the comparison is no longer apples-to-apples. `make check` does **not** run integration (`check-integration` is separate). Decide: (a) update the path + compare `.wayforge-managed` (TS) vs `.ai-config-managed` (legacy) with both excluded from `diff`; (b) drop the legacy arm; or (c) leave the already-stale test untouched (out of scope).
2. **Preserved set confirmation.** `docs/ai/reports/**` is treated as historical and preserved alongside plans/ADRs/logs. Confirm this is acceptable.
3. **Snippet helper renames.** Renaming `ai-setup-repo*`/`ai-uninstall-repo*` to `wayforge-*` and `_ai_config_root` to `_wayforge_root` is a clean-break behaviour change for anyone sourcing the snippets. Confirm the new names.
4. **CHANGELOG history.** Keep historical `[x.y.z]` link lines pointing at the old repo URL (GitHub redirects the rename); only the `scripts/release.ts` template and the new v1.0.0 entry use `Macacoders/wayforge`. Confirm.
5. **Version bump.** Bumping `VERSION` to `1.0.0` and cutting the tag are release mechanics (`scripts/release.ts --set-version`) and are **out of scope** here. Confirm the rename lands before the release step.
