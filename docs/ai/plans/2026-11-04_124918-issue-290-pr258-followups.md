### Task 2: Split the `gh` credential failure-mode tests

**Objective:** Give "`gh` absent" and "`gh` present but unauthenticated" distinctly named tests that assert actionable guidance, exit 1 at the CLI boundary, and no credential/subprocess-output leakage.

**Files:**
- Modify: `tests/typescript/gh-issue/gh-issue.test.ts:306-351`
- Modify: `tests/typescript/gh-issue/e2e.test.ts` (auth integration block)
- Validate: `npx vitest run tests/typescript/gh-issue`

**Step 1: Establish expected behaviour**

Both failure inputs must reach the same controlled error in `resolveToken()`:

- `execFileSync` throws `ENOENT` because no `gh` executable exists.
- `execFileSync` throws because `gh` exists but `gh auth token` exits non-zero (unauthenticated).

In both cases the thrown message contains the `GITHUB_TOKEN` fine-grained-PAT guidance and the `gh auth login` alternative, the raw subprocess output is not included, and nothing is written to stdout/stderr. When run through the CLI entry guard, the process exits 1.

**Step 2: Add or update validation**

In `gh-issue.test.ts`, replace the existing `it.each` block with three separately named cases:

1. `throws actionable guidance when gh is not installed (ENOENT)` — mock `execFileSync` to throw an error carrying `code: 'ENOENT'` and a sentinel message such as `gh-credential-sentinel`.
2. `throws actionable guidance when gh is installed but unauthenticated` — mock it to throw an error carrying `status: 1` and the same sentinel.
3. `throws actionable guidance when gh returns an empty token` — keep the existing blank-token case.

Each case should delete `GITHUB_TOKEN`/`GH_TOKEN`, capture `process.stdout.write` and `process.stderr.write` with `vi.spyOn`, and assert:

- the rejection message contains `GITHUB_TOKEN to a fine-grained personal access token for this repository` and `gh auth login`;
- the rejection message does not contain `gh-credential-sentinel`;
- the stdout and stderr spies received no writes.

In `e2e.test.ts`, keep the existing absent-`gh` test (it already asserts exit 1) and add `exits 1 when gh is installed but unauthenticated`:

- Create a temporary directory with a failing `gh` executable. On POSIX symlink `process.execPath` to `<dir>/gh`; on Windows hardlink (fallback copy) `process.execPath` to `<dir>/gh.exe`.
- Run `check` with `GITHUB_TOKEN: ''`, `GH_TOKEN: ''`, and `PATH` prefixed by that directory.
- Assert `status` is 1, `stderr` contains both guidance phrases, and neither `stdout` nor `stderr` contains the child process's own output (`Cannot find module`).
- Clean up the temporary directory in a `finally` block.

The fake "gh" is the real Node executable, so invoking it as `gh auth token` fails non-zero without depending on a real GitHub CLI or shell shims (Windows cannot execute a `.cmd` through `execFileSync` without `shell: true`).

**Step 3: Write minimal implementation**

Implement the three unit cases and the e2e helper/test. Do not change `resolveToken()`; its catch-and-rewrite behaviour already satisfies the contract, and this task is about pinning it.
